This is the **logical** data model derived from the requirements. The database engine is **PostgreSQL** (decision D-4), so types are given as PostgreSQL types. Data & Database decides the remaining physical details (indexes, naming, migrations). The ER diagram is in [diagrams/erd.md](diagrams/erd.md).

**Notation:** PK = primary key, FK = foreign key, UQ = unique, NN = not null, `?` = nullable.

> **PostgreSQL notes:** enumerations below can be created as native types (`CREATE TYPE transaction_type AS ENUM (...)`) or as `varchar` + `CHECK`. Use `numeric(14,2)` for money (NFR-08), `timestamptz` for timestamps and `jsonb` for audit values.
>
> **Naming tip:** `transaction` is a reserved word in several SQL dialects — use the table name `transactions` (plural) or `money_transaction`.

## TRANSACTION

The central entity. **A transaction is any money movement, not only an expense.**

| Attribute | Type | Constraints | Description |
|---|---|---|---|
| transaction_id | integer | PK | |
| family_id | integer | FK → FAMILY, NN | Tenant key (NFR-03) |
| type | transaction_type | NN | INCOME / EXPENSE / TRANSFER (BR-01) |
| amount | numeric(14,2) | NN, CHECK > 0 | Always positive (BR-02) |
| source_account_id | integer? | FK → ACCOUNT | Money leaves this account. Required for EXPENSE, TRANSFER; NULL for INCOME |
| destination_account_id | integer? | FK → ACCOUNT | Money enters this account. Required for INCOME, TRANSFER; NULL for EXPENSE |
| category_id | integer? | FK → CATEGORY | Required for INCOME/EXPENSE; NULL for TRANSFER |
| transaction_date | date | NN, ≤ today | Date the money moved (BR-09) |
| description | varchar(255)? | | Free text, searchable (FR-21) |
| created_by | integer | FK → FAMILY_MEMBER, NN | Who recorded it |
| recurring_rule_id | integer? | FK → RECURRING_RULE | Set if generated automatically |
| is_deleted | boolean | NN, default false | Soft delete (BR-11) |
| created_at | timestamptz | NN | |
| updated_at | timestamptz | NN | |

**Suggested CHECK constraint (BR-03 – BR-05):**

```sql
CHECK (
  (type = 'INCOME'   AND source_account_id IS NULL     AND destination_account_id IS NOT NULL AND category_id IS NOT NULL) OR
  (type = 'EXPENSE'  AND source_account_id IS NOT NULL AND destination_account_id IS NULL     AND category_id IS NOT NULL) OR
  (type = 'TRANSFER' AND source_account_id IS NOT NULL AND destination_account_id IS NOT NULL
                     AND source_account_id <> destination_account_id AND category_id IS NULL)
)
```

**Suggested indexes:** `(family_id, transaction_date)`, `(source_account_id)`, `(destination_account_id)`, `(category_id, transaction_date)`.
